# Sprint 收尾手册

所有卡片 Done、验收通过后，进入 Sprint 收尾阶段。

---

## 第一步：项目升级

### 1.1 文档同步

每个 Sprint 完成后，审查并更新以下文档：

- **README.md** — 基本肯定会变（新功能、新命令、截图更新）
- **CLAUDE.md** — 项目约定、目录结构、技术栈有变化时要更新
- **DESIGN.md** — 本 Sprint 如果新增了 UI 模式或设计规范，补充进去

审查标准：一个新成员读完这些文档后，能否理解当前项目状态？

### 1.2 测试进化

基于本 Sprint 所有 bug issues 的根因，进化现有测试：

1. 回顾所有 bug issue，按类型分组（状态机、渲染、遗漏等）
2. 对每种 bug 类型，判断现有测试能否覆盖：
   - **能覆盖** → 已有测试不变
   - **不能覆盖** → 新增测试用例（优先 BDD，必要时补 TDD）
3. 新增测试写在对应的模块测试文件中
4. 运行 `go test ./... -count=1` 确保全绿

目标：每个 bug 的根因都有测试覆盖，防止同类型 bug 回归。

---

## 第二步：打 Tag

给代码仓库打 tag，名称与 Sprint 名称一致：

```bash
git tag -a sprint-1 -m "Sprint 1"
git push origin sprint-1
```

---

## 第三步：Sprint 总结报告

在计划仓库的 Discussions 下，按以下格式创建 Sprint 总结报告，category 选择 `General`。报告中引用 Sprint Board 链接和 tag 名称：

```markdown
# Sprint <N> 完成报告

> **Sprint Board:** <看板链接>
> **Tag:** [`sprint-N`](https://github.com/<owner>/<repo>/tree/sprint-N)

---

## 完成概览

- **用户故事:** <N> 个（全部 Done）
- **技术改进:** <N> 个（全部 Done）
- **Bug 修复:** <N> 个（全部 Closed）

### 用户故事

| 编号 | 标题 | 状态 |
|------|------|------|
| US-01 | 标题 | Done |

### 技术改进（可选，没有则略过）

| # | 标题 |
|---|------|
| N | 标题 |

### Bug 修复

| # | 标题 |
|---|------|
| N | 标题 |

---

## 范围确认

### 已完成
- [x] 功能点

### 本次不包含
- 功能点 — 后续计划

---

## Bug 分析

### 分类统计

| 类别 | 数量 | 占比 |
|------|------|------|
| 状态机 | N | N% |

### 状态机 (N 个)

**#N 标题** — 根因描述

### 遗漏 (N 个)

**#N 标题** — 根因描述

### 布局/渲染 (N 个)

**#N 标题** — 根因描述

### 其他 (N 个)

| # | 类型 | 标题 |
|---|------|------|
| N | 类型 | 标题 |

---

## 测试改进

基于 bug 模式，新增 **N 个测试函数、N 个测试用例**：

| 测试 | 用例数 | 防回归 |
|------|--------|--------|
| TestName | N | #N 描述 |
```

---

三步完成后，Sprint 正式结束。

### 第四步：关闭 Sprint 看板

```bash
gh project close <看板编号> --owner <owner>
```

旧看板关闭后仍可访问（只读），记录在 Sprint 总结报告的链接中。

---

进入下一个 Sprint 的规划阶段。
